关于我

我是李广明，做 AI Infra 和平台工程。目前主要为具身智能研发搭基础设施。我的工作从宿主机、网络、存储和身份入口开始，到 GPU 分配、模型服务和研发环境交付。研发团队拿到环境之后，还要能复现实验、定位慢在哪里，并知道一次变更出了问题怎么撤。

过去十多年，我从企业 IT 和系统集成做起，做过存储、虚拟化和客户现场交付。早年的工作教会我看主机 I/O、算维护窗口和留恢复路径。现在做推理平台，问题换成了共享 GPU、模型服务和 Agent，排查时仍然要把这些基础问题讲明白。

工作中的几个案例

具身智能边缘推理，从分配 GPU 到核延迟

负责两类 GPU 负载的部署和调优。L40S 面向桌面和基础服务走普通 vGPU，RTX PRO 6000 面向边缘推理用 MIG 切分。我从宿主机配置做起，逐轮对比来宾资源放置、绑核和切分变更。固定物理核让迁移次数归零，P95 却升了 0.72 ms，因此没有保留。另一组四路共卡试验里，模型层均值约 204 ms 降到 115 ms，文章保留了同时改变的内存策略与未跑完的端到端验证。看三轮调优怎样验收

身份和运维入口，从能登录到能追查

做过本地与云上的域控部署，也负责堡垒机、目录组映射及会话审计的落地。一次部分网站连接返回 500 时，平台登录和容器探针仍然正常。我从连接分配定位到遗留应用记录，只停用受影响对象，再走真实浏览器连接并核会话、录像。后来拿测试对象验证了 Agent 通过 API 创建、授权、回读和清理，收权后的全流程演练仍单独记录。跨站点域控、DNS 和复制 · 堡垒机故障复盘和 Agent 纳管

个人实验和公开项目

工作外，我用 DGX Spark 配本地推理，分别测引擎、网关和真客户端。长输入测试到 250046 个 token，核的是指定标记能否找回。Codex、WorkBuddy 走端到端验证，另外两类客户端保留协议层的验证边界。家里的知识库也用多套算力，我写了路由与摘流记录，把自动回退和主动让卡分开验证。DGX Spark 上的长上下文和 Agent 接入 · 知识库推理和算力取舍

我也独立做过一些离用户更近的工具。Moonlight macOS 增强版聚焦客户端设置和串流诊断。飞牛 NAS 视频处理应用从目录预检做到分片恢复、成品解码和结果回读。哪些功能跑过、哪些版本能下载，文章和公开项目放在一起。Moonlight 的设置、打包和实机记录 · 飞牛视频处理的权限与验收

为什么写这个博客

我用博客留住项目结束后最容易忘的几件事：当时缺什么，为什么选这条路，搞砸过什么，最后拿哪条数据验收。对 AI Native 和 Agent，我也沿用这个习惯。监控告警、工具调用、人工批准和业务回验，分别有可核对的边界。我正在验证的 Agent 运维路径

欢迎交流 AI Infra、推理平台和基础设施工程方向的机会。代码放在 GitHub，博客源码在 bsligm/blog，也可以通过联系页找到我。
