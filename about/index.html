关于我

我是谁

AI Infra 工程师 / 平台工程 / 场景交付。 10 年以上企业基础设施与技术交付经验，兼具甲方 IT 管理、公司级平台从 0 到 1 建设，以及机场、设计云、超算云这类大型客户现场交付能力。现在在一家具身智能创业公司从 0 到 1 搭整套基础设施，面向 VLA 模型研发：把通信、算力、模型环境、数据协同与可观测组织成统一平台，用实机基准和恢复验证支撑持续交付。

一句话：别人交付的是机器，我交付的是一条能自我观测、可复现、回滚得掉的研发链路。

我信奉的事

  • 架构视野 · 工程纵深 · 独立交付。 方案要能画成架构图，落得要能回滚，结的账要有数字。
  • 量化口径先行。 每个性能数字都带统计口径——不拿「感觉变快了」交差。
  • 证据说话、先给结果。 每一步可复现，每个结论可回查；API 返回 200 不算业务证据，真流量跑通才算。
  • 确定性自动化 + 智能体调查分工明确。 能用脚本钉死的不交给 Agent，Agent 负责调查与决策，人负责验收。

AI Native 是我在押注的事

这是我目前最想推进的一件事：让基础设施本身变成 Agent 的原生环境，而不是往传统运维里再塞几个 AI 功能。

五维基准——我给自己定的框架，用来给任何「AI Native 化」提案做一致性检查：

  1. Agent-first OS：Agent 是一等公民，OS 和工具链先为它设计，人反而成了二等用户。
  2. 数据写入即语义化：落盘的那一刻就带上下文、带口径、带归属，事后不用人再去「考古」。
  3. 事件驱动 Agent Swarm：不是人点一下跑一次，而是事件触发一群有界、可复核的 Agent 自动协作。
  4. 知识自动回流：这次踩的坑，自动变成下次 Agent 的上下文——经验不再只存在某个人脑子里。
  5. 自然语言操作面：最终操作界面就是人话，命令行是给人看的降级方案。

当前栈自评 v2.0 · AI-Augmented：Zabbix 是眼睛、堡垒机是手、Agent 是大脑、知识库是记忆——各能各干，但还靠人做中枢调度。v3.0 事件驱动的多 Agent 协作已经在路上。

  • 受控 Agent 协作：日常研发已经跑在「主控拆解 → 专项 Agent 执行 → 独立复核 → 知识回流」的分工上。场景隔离、有界重试、实机回读——Agent 干完的活要留证据链，不是黑盒。
  • Agent 接入即服务：从单卡 256K 上下文的本机推理，到 vLLM + LiteLLM 统一给 Codex、Claude Code 等主流 Agent 客户端供模型。并发策略、多模态图片识别、各家协议兼容性调试——全是踩坑踩出来的，博客里有完整记录。
  • 知识自动回流：WeKnora 知识库按家庭 / 公司分场景双向读写，任务事件、可复用规程、踩坑记录自动沉淀成下一次 Agent 的上下文。团队的经验第一次不再是「离职就带走」的资产。

六大能力面

  • 公司级架构与大型交付。 独立承担一家具身智能创业公司基础设施从 0 到 1；主导某大型机场 AI 算力、某建筑设计云、某设计院超算云的基础设施交付——既能画架构，也能蹲在机房盯验收。
  • 异构算力与性能工程。 PVE 承载 L40S / RTX PRO 6000 / DGX Spark，MIG / vGPU / SR-IOV 切分 + CPU 亲和 / NUMA 拓扑调优，把数据中心级 GPU 切成研发团队可按需领取的推理资源；每个调优结论都带同条件 A/B 口径。
  • 网络架构与多云互联。 M-LAG 双机聚合、100GE 骨干、VLAN 分区；多云 IPsec 现网联通 + 万兆裸光纤目标架构，支撑成果跨区域演示分发。
  • 混合身份与零信任治理。 飞书（组织主数据）→ 飞连（口令权威）→ AD（本地资源权限）的职责链设计，Entra ID 云身份在下游规划；同口径人员同步迁移身份匹配 100%，单轮同步耗时缩短近一半。
  • 研发平台与交付工程。 自研 Go 控制面 + GitLab CI，贯通实验环境复制、模型数据共享、GPU 许可与 CI 构建；CI 验证轮 4/4 作业通过，形成可复用、可诊断、可恢复的交付链路。
  • AI Native 与 Agent 协作。 结合知识检索、模型服务与受限智能体，沉淀可复用工具和规程，让「受控交付」成为默认工作流。
