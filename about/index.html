关于我

我是李广明，做 AI Infra。现在负责具身智能团队的研发基础设施，从宿主机、网络、存储和身份做到 GPU 推理环境。做企业基础设施十多年，最早做系统集成和企业 IT，后来转到算力和研发平台。

我的 AI Native

我希望交给 Agent 一件事，它能自己查到现场，按授权做完，把结果留下来。家里先拿运维试。比如推理服务掉线，监控告诉 Agent 哪个实例、什么时候开始报错，Agent 查进程和日志，再带着证据来问要不要恢复。获准后用已有的运维入口处理，发一条真实推理请求确认恢复，最后把这次怎么查的写回知识库。

我给自己定了五个维度。做新项目时，也拿这五条看看哪些已经用得上。

  1. Agent-first OS。设计系统和工具时，把 Agent 当作操作者。给它可调用的接口、明确的权限和能判断成败的结果。查资产和授权用 JumpServer 的接口，读目标机的状态则走已获准的主机通道。
  2. 数据写入即语义化。记录产生时就带上对象、时间、来源和验证结果。比如推理入口的健康检查通过了，实际模型请求有没有做过，在记录里各写一项。
  3. 事件驱动 Agent Swarm。告警带着对象和时间窗发起调查。调查 Agent 收证据，执行 Agent 接获准的任务，复核 Agent 再查一次实际服务。这条以后还要试告警重复、执行到一半断线等情况。
  4. 知识自动回流。把这次查到的东西、怎么处置、结果能用到什么范围，写回 WeKnora。下回查到旧记录，先对照今天的版本和状态，再决定哪些步骤值得沿用。
  5. 自然语言操作面。我可以直接说「继续上次那台机器的排查」，Agent 要能找回对象、上次的结果和停在哪一步。谁有权改什么，仍按原来的权限和审批来。

我把现阶段叫 v2.0 AI-Augmented。家里的 Zabbix 已经能报异常，Agent 能查状态和旧记录，JumpServer 或现有工具负责受控执行，任务结果可以写回 WeKnora。这几段各自用过，目前还是人发起调查。下一步我想先跑通一条告警自动发起只读调查的链路，拿到结果后再由人决定要不要动服务。AI Native 的五维和一次推理故障 · WeKnora 的本地模型路由

现在的工作

团队建设研发环境时，我从第一批宿主机、共享存储和网络做起。研发进来以后，每个人要能找到自己的环境、读到该读的数据、用上需要的 GPU。换一套驱动或模型环境，还要能照原条件把之前的实验跑出来。模板、权限和构建环境都是为这些事准备的。

也做过用 Go 写的控制面和 GitLab CI，把实验环境复制、构建放到固定的入口。交接时要告诉接手的人，环境基于哪个模板、依赖哪个构建结果、数据从哪取、权限谁来改。隔几周有人来复现实验，可以顺着这些记录重建一份。

GPU 这块做过桌面 vGPU，也做过具身智能模型的边缘推理。桌面看的是多台来宾能不能稳定使用，推理还要看固定节拍下四路共卡会等多久。一组现场对照里，四路模型调用均值从约 204 ms 降到约 115 ms，当时同时改了 GPU 切分和内存放置。这个数是模型调用的实测，我把测试条件和其它几轮的结果都放在PVE 和边缘推理那篇。

身份和远程运维这块，我做过跨站点域控，也做过JumpServer 的目录接入和资产授权。目录、堡垒机和共享存储往往是研发拿到机器时先要用到的三样东西。我把它们跟推理环境放在同一次交付里检查。

早期工作和个人项目

最早做系统集成，我在客户现场做过服务器、存储和虚拟化。后来在企业里负责过 IT，从日常运维、备份到供应商交付，遇到问题得把几方约到同一个窗口里。再往后做算力交付，接触了设计云和超算云项目。装完机，要和客户一起查共享存储、网络，最后跑一遍他们实际要用的应用。现在具身智能这边的基础设施也是从头做起。

PowerStore 升级、Atlas 800 装机和第一台域控都是早期的笔记。做存储升级时，要看主机侧多路径和业务读写。后来做模型服务，同样要请实际使用的人从原入口跑一次，把变更前后的结果放在一起看。

家里有一台DGX Spark，Codex 和 WorkBuddy 接到本地模型上。有次测试输入约二十五万 token，前、中、后各放一个标记，模型找回了三个值。工具调用、会话压缩也逐项试过。有些客户端我只做了协议验证，文章里各自记了。

视频处理是另一个项目，我给飞牛写了超分和插帧应用。开始是想在网页选完片子就让它一直跑。做下去才发现，权限要在提交前先查，进程重启后要从已确认的分片接着跑，最后还得打开成品确认能解码。我也改过Moonlight 的 Mac 客户端，主要是设置、设备识别和串流测试。

我在看 AI Infra 和推理平台方向的机会。工作、项目或文章里有想聊的地方，都可以联系我。
