在 Windows Server 上搭第一台域控

发表于2021-05-06|更新于2026-11-23|桌面维护服务器管理
|总字数:3k|阅读时长:9分钟|浏览量:

2021 年搭第一台域控，我要先把域账号、计算机对象和组策略放到同一个地方。终端管理、BitLocker 恢复信息和 LDAP 应用后来都用到了这套目录。下文用的是当年的安装界面，步骤从新建域的第一台域控讲起。

首台 DC 交付后，真正能验的是客户端能否通过 DNS 找到它、加域后能否用测试账号登录、能否取到预期组策略。复制和站点切换要有第二台域控才能验证。跨场地后的问题见 三台域控部署实录。

关键设计决策

提升向导跑完之前要做的几个决策，代价一并列出：

决策 为什么这么选 代价
计算机名在提升前定稿 改名牵动已下发的组策略引用、计算机对象、按名称写死的脚本与共享路径 命名要一次想好体现机房、角色与序号；超 15 字符被 NetBIOS 截断
固定地址和可解析域区的 DNS SRV 记录决定客户端能否定位到 DC。首台 DNS 尚无同域伙伴时可以使用本机，增补域控时按现场域内 DNS 规划配置 变更地址后回读 A、AAAA、SRV 记录和客户端 DC 定位，避免残留指向旧地址
单台域控 可以先验证小型域的加域、认证和策略 没有复制伙伴。单点停机时无法提供新的域服务，部分客户端可能凭缓存凭据本地登录
AD 数据库、日志、SYSVOL 保持系统盘默认 只有一块盘，分盘徒增恢复路径 单盘故障全失，依赖 System State 备份加一次真实还原演练

系统安装准备

除 U 盘安装介质外，也可以通过 iDRAC 等带外管理接口挂载镜像远程安装。

1. U 盘安装方式

使用 U 盘安装介质时需要注意以下事项：

  • 如果服务器有阵列卡，需要提前到品牌官网下载对应驱动，否则可能无法识别磁盘
  • 准备好 Windows Server 安装镜像文件和可启动的 U 盘

2. 远程管理安装方式

以 DELL 服务器为例，使用 iDRAC（IPMI 接口，各家厂商名称不同）进行安装：

  • 在 BIOS 中配置好 iDRAC，并接入本地局域网便于日后管理，或者使用网线直连 PC
  • DELL 服务器 iDRAC 的默认管理地址通常为 192.168.0.120（以随机标签与机型文档为准）
  • 线缆连接完成后在 BIOS 中配置地址以及管理密码

3. 服务器开机从镜像启动

开机后按自检画面提示的快捷键进入一次性启动菜单（Dell 机型通常为 F11，其他机型以画面提示为准），选择 U 盘或 iDRAC 虚拟光驱作为启动设备。

系统基础配置

在安装完成 Windows Server 系统后，需要进行一些基础配置：

1. 更改计算机名和固定 IP 地址

  • 计算机名在提升为域控之前定稿。改名会牵动已下发的组策略引用、已加域计算机的计算机账户，以及按名称写死的脚本与共享路径，域控上线后再改的成本远高于现在多想两分钟。名称超过 15 字符会被 NetBIOS 截断，命名建议同时体现机房、角色与序号，第二台域控直接顺延。
  • 网卡设为静态地址，DNS 首选填本机 127.0.0.1（已有域内 DNS 时指向该地址）。这一步做扎实，下一步的预安装检查就不会因此报错；DNS 角色要到下一阶段才安装，此刻指向本机暂时解析不了任何域名属预期状态，处理方式见「注意事项」。
  • 两项都改完后重启一次，再进入角色安装，避免中途改地址导致已注册的 DNS 记录与实际不一致。

2. 配置域控制器

角色安装完成并不会让本机成为域控，还要再执行提升操作。向导一共八页，逐页截图对复现没有价值，真正需要盯住的取值集中在下表：

向导页 关键界面项 实际要注意的取值
1 部署后配置 「将服务器提升为域控制器」 入口在角色安装完成后的提示或「服务器管理器 → 通知」里，关掉提示仍可从通知区重新进入，不必重装角色
2 部署配置 操作类型 全新环境选「添加新林」，为已有域增补域控选另一项。两者后续可选项不同，选错只能退出向导重来
2 部署配置 DNS 域名与 NetBIOS 域名 两者上线后都不可更改，向导是唯一一次可以改的机会。域名建议用与对外域名隔离的子域或独立后缀，NetBIOS 名取域名首段，超过 15 字符会被截断
3 域控制器选项 DNS 服务器、全局编录、只读域控制器 新林首台域控的 DNS 与全局编录默认勾选且不可取消，AD 与 DNS 同机是硬要求；只读域控制器仅用于无法物理防护的分支站点，总部域控不选
4 其他选项 林/域功能级别 决定可用特性与域控最低系统版本，提升后基本无法回退，按现网最老的域控版本选取
4 其他选项 数据库、日志、SYSVOL 路径 默认全部落在系统盘。数据库与日志分盘能降低单盘故障时的恢复难度，只有一台盘就别硬拆，保持默认更好维护
4 其他选项 启用回收站 误删对象的恢复成本差别很大。它是满足林功能级别条件后的独立操作，通常在部署后评估启用。启用后不可关闭
5 目录服务还原模式密码 DSRM 密码 AD 数据库异常、域内无其他域控可登录时，这是唯一的本地登录通道，必须纳入密码保管流程，且不要与域管理员密码复用
6 确认 摘要页 此页只是回放前几步的选择，值得逐行核一遍的是域名与功能级别，变更代价高，功能级别回退也受版本和特性约束
7 预安装检查 验证结果 失败最常见的两个原因是 DNS 指向错误与网卡未设静态地址。修正后点「重新测试」即可，不需要回退上一步重填
8 安装 自动重启 校验通过即开始安装并自动重启，期间不要强制断电；重启完成后部署才算结束

留档可以记录域命名、功能级别、预安装检查结果和 DSRM 凭据的受控保管位置。不要截取或保存含凭据的页面。

验证域控制器功能

安装完成只说明向导跑完了。下面四条分别核域控自身健康、复制状态、域名解析与 DC 定位、客户端实际登录，每条都给出可判定的通过标准：

  1. 域控自检：在域控上执行 dcdiag /v，逐项应为 Pass。测试项较多，输出较长时先看结尾的汇总行，再回读报 FAIL 的那一项。
  2. 复制状态：repadmin /showrepl 应显示复制成功。单台域控没有复制伙伴，返回「没有伙伴」属正常，此时该项只能作为基线留存，等第二台域控上线后才有实际意义。
  3. 域名解析与 DC 定位：在域控上执行 nslookup -q=srv _ldap._tcp.dc._msdcs.<域名>，应返回本机地址；在客户端执行 nltest /dsgetdc:<域名>，应返回域控主机名与站点。解析不到 SRV 记录，问题基本在 DNS 指向，而不是域服务本身。
  4. 客户端加域：加域后注销并重新登录，在客户端执行 echo %logonserver%，应返回域控的计算机名。拿到这个值才说明这台机器实际走完了域认证，而不只是本地缓存了旧凭据。

图形界面下还可以打开「服务器管理器」查看「通知」区域有无报错，以及用「Active Directory 用户和计算机」确认域与组织单位结构，但这两处只能看出「界面能打开」，不能替代上面的判据。

注意事项

  • DNS 是硬依赖。域控制器同时承担 DNS 角色，网卡的 DNS 必须指向本机（或已有的域内 DNS），指向公网 DNS 会导致 SRV 记录解析不到、客户端加域失败。
  • 上游转发单独配。域内 DNS 接管后要在条件转发器或根提示里补上外部解析出口，否则内网解析正常、外网全断，容易被误判成域服务故障。
  • 静态 IP 不可协商。地址变更会让 _msdcs 区域记录与实际地址不一致，故障表现为间歇性登录变慢而非直接报错，排查成本很高。
  • 备份要含 System State。只备份文件卷无法还原 AD 数据库，域控备份必须走包含 System State 的方案，并按组织恢复点目标、复制状态、备份保留期和恢复路径核对。

总结

这台域控制器的交付路径很短：装系统 → 改计算机名与静态 IP → 添加 AD DS（按需含 DHCP）角色 → 提升为域控制器并集成 DNS → 重启后以「服务器管理器通知无报错、ADUC 可见域结构、客户端成功加域」三步收口。

链路里有两处事后很难补救：域名与 NetBIOS 域名上线后再变更代价极高，向导第 2 步就要按最终命名填写；DSRM 密码是 AD 数据库异常时唯一的本地登录通道，必须纳入密码保管流程，不能作为向导里一次性的过场。

装出一台能响应的域控以后，我还会按下面的顺序补三项实测。

  1. 第二台域控制器。把在线身份服务的单点与备份分开设计。单台 DC 故障会影响新的认证、加域和策略读取。仍应保留独立且可读的备份。
  2. 还原演练。在隔离环境按实际故障场景确认 System State、AD DS 和 SYSVOL 的处理。林恢复首台可写 DC 与修复单台故障 DC 的要求不同。例如微软现行 林恢复指南 对首台可写 DC 区分 AD DS 非权威还原与 SYSVOL 权威还原。本文没有实际恢复报告。
  3. 时间同步与站点规划。Kerberos 对时间偏差敏感，PDC Emulator 角色持有者要指向可靠的 NTP 源。多场地部署还需提前在「AD 站点和服务」登记子网，否则客户端会跨场地认证与复制。

第一台域控起来时，我只在小范围验证加域、登录和组策略。OU 怎样分，账号怎样进出，统一策略怎么推，是后面的活。放在同一个窗口里改，问题出来很难判断从哪一步查。
